## 第 2 步：录之前先自检摄像头（关键，别跳过）

```cmd
python cam_calib.py
```

它弹 5 秒窗口，输出三行判定：

| 输出 | 意思 | 动作 |
|---|---|---|
| 三项全 `[OK]` + conf ≥ 0.50 | 这个位置能录 | 直接进第 3 步 |
| 有 `[调整]` | 距离/光线/对焦 | 按提示改，重跑 |
| 出现 `[换机]` | 手贴到最近还不够大 | **换外接摄像头或换电脑，别再调参数** |

## 第 4 步：录素材，用 app.py

```cmd
python app.py
```

浏览器打开它打印的地址（通常是 `http://127.0.0.1:7860`）。

### ⚠️ 界面上那个「置信度过滤阈值」滑块（最容易踩的坑）

**这个滑块默认已改成 0.60**（原来是 0.75，会把结果全过滤掉）。

原因：单级 YOLO 实测字母置信度均值约 **0.67**，而 app.py 会在识别之后再按滑块阈值
过滤一次。实测同一个结果：

```
滑块 0.75 → 全部被过滤 → 界面显示「⚠️ 识别失败：未检出有效手语词序列」
滑块 0.60 → 正常显示「哪里 (0.68)」+ 政务回答
```

**同一个识别结果，只因阈值不同，一个报失败、一个出结果。**
现场如果发现"明明打对了却说识别失败"，**第一件事是把滑块往左拉到 0.50~0.60**，
不要怀疑模型，更不要去改 MIN_RUN。

> 什么时候该往右调（0.65~0.70）：镜头条件很好、conf 稳定在 0.7 以上时，调高能减少误识别。
> 宁可少识别也别识别错，录制时可以试两档比较效果。

**录制流程建议（评委看得懂的顺序）：**

1. 开场 5 秒：露出环境（桌面、摄像头），证明是实时运行
2. 点「开始识别」→ 打 `n-a-l-i` → 停顿 1 秒 → 界面出结果
3. 接着打 `y-i-b-a-o` → 看问答区是否给出医保相关回答
4. 故意打错一个字母，展示系统的容错/纠错提示（**这是加分项**）
5. 断网或把 `.env` 里 `USE_REAL_LLM_API=0`，再演示一次 → 说明有本地降级

**录制参数：**

- 分辨率 1080p，30 fps，别用手机美颜
- 录制时**只录浏览器窗口**，别录整个桌面（避免泄露别的窗口）
- 每条素材控制在 30~60 秒，录 3~5 条备选

## 今天可能踩的坑（对号入座）

| 现象 | 处理 |
|---|---|
| 摄像头打不开 | 关微信/钉钉/腾讯会议/相机 App，它们会独占摄像头 |
| app.py 打开是空白页 | 等 10~20 秒（gradio 首次启动慢），刷新一次 |
| 识别不出字，框也不出 | 跑 `cam_calib.py`，八成是手太小（坐太远） |
| 有框但 conf 一直 0.3~0.4 | 画质/距离问题；`hand` 那项低于 0.45 就是凑近 |
| 问答回的是模板话 | key 没填或没重启 app.py；先跑 `check_llm.py` |
| 某个字母拼命认错（Z/ZH、C/CH、S/SH） | 这两组模型本身就分不清，**避开含这些字母的演示词** |
| 报 `ModuleNotFoundError` | 昨天装依赖用的可能不是同一个 Python，用 `python -m pip install -r requirements.txt` |
