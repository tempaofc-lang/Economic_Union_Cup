## 1. 为什么现在就要写这个

我们的风险不在于"做不出来"，而在于 **A 组交来的东西和我们预期的形态不一样**：

- 我们以为拿到的是「输入一张图 → 输出"身份证"这个词」；
- 实际可能拿到的是「输入一张图 → 输出手部框和 21 个关键点」，**分词还得我们自己想办法**。

这两种情况，工作量差 3 倍。所以第一件事不是写代码，是**把问题问清楚**。

## 3. 三种可能的模型形态，我们怎么接

### 形态 A：多类别检测（最理想，我们最省事）

模型直接把手语词当类别，一帧输出 `{cls: 2, conf: 0.93, bbox: [...]}`，`names[2] = "身份证"`。

**我们的工作**：`inference.py` 里直接 `model.names[int(cls)]` 拿词，进抽帧去抖。**约 1 天完成。**

### 形态 B：只检测手部 + 需要另外的分类器

模型只告诉你"手在这"，不给词。

**我们的工作**：需要二级分类器。**这是最坏情况**，16 天内自己做分类器风险极高。应对顺序：
1. 先请杨李灿（A 组分类模型负责人）直接给一个 `classify(hand_crop) -> word` 的函数或脚本；
2. 拿不到就**把词库缩到 5 个**（您好 / 身份证 / 丢失 / 补办 / 谢谢），用关键点做简单模板匹配；
3. 再不行，退回形态 C 的演示方式。

### 形态 C：暂时什么都拿不到

**我们的工作**：`yolov8n.pt`（官方预训练，能检测"人"和"手"附近区域）跑出**真实边框**，词用预置序列。演示时字幕说明"视觉分词由 A 组负责"。

> 形态 C 的成品依然满足 §8 的三条底线要求 —— **框是真的、流程是真的、只有词是预置的**。这在评审里是可以接受的降级，前提是**如实说明**。

## 4. 我们这边的契约（B 组对外的承诺）

### 4.1 唯一入口函数

A 组的模型最终必须藏在这个函数背后，界面只认它：

```python
# vision_engine.py
def predict_sign_tokens(source_type="本机摄像头实时采集", video_file=None, conf_thresh=0.75):
    """
    返回: (custom_rgb_frame, raw_tokens, scene_meta)

    参数
      source_type : "本机摄像头实时采集" | "上传本地视频文件"
      video_file  : 上传视频的本地路径（source_type 为摄像头时为 None）
      conf_thresh : 业务阈值（0.50~0.95），由界面滑块给出

    custom_rgb_frame : np.ndarray(RGB, 480x760) 或 None
                       —— 返回 None 时，界面会自动按 bbox 自己画框（推荐，省事）
    raw_tokens       : [{"word": str, "conf": float, "bbox": (x1,y1,x2,y2)}, ...]
                       —— **不要在这里按业务阈值过滤**，界面会自己过滤并展示被过滤了几个
    scene_meta       : {"scene_name": str}  用于状态栏显示
    """
```

**两条铁律**：
1. `raw_tokens` 不按 `conf_thresh` 过滤 —— 否则"已过滤 N 个低置信度动作"这个演示点就没了。
2. `bbox` 必须是**原始视频坐标系**的整数像素，不要归一化，不要裁剪缩放。

### 4.2 共享词表 `vocab.json`

放在 `手语识别系统/vocab.json`，A 组和 B 组**以它为准**：

见仓库文件 [`手语识别系统/vocab.json`](../../手语识别系统/vocab.json)，共 **17 类** = 16 个政务高频词 + 1 个确认手势：

```json
{
  "version": "1.0",
  "confirm_word": "确认",
  "classes": {
    "0": "你好",  "1": "请问",  "2": "身份证", "3": "丢失",
    "4": "补办",  "5": "社保卡", "6": "医保",   "7": "激活",
    "8": "窗口",  "9": "哪里",  "10": "营业执照", "11": "办理",
    "12": "需要", "13": "什么",  "14": "材料",  "15": "谢谢",
    "16": "确认"
  }
}
```

改词表 = 改这一个文件 + 通知双方，**不许各自写死在不同地方**。
注意 `vocab.json` 的 id 顺序必须与 A 组 `model.names` 完全一致，联调时先打印比对（见 §6 第 3 步）。

### 4.3 串词规则（B 组自己定，不依赖 A 组）

| 参数 | 默认值 | 含义 | 谁调 |
| :-- | :-: | :-- | :-- |
| `frame_stride` | 5 | 每 5 帧推理一次（25fps → 5 次/秒） | 吴夏云按 CPU 速度调 |
| `stable_frames` | 5 | 同一词连续出现 5 次抽帧才算数（≈1 秒） | 按实测调 |
| `same_word_gap` | 8 | 同一个词再次出现要间隔 8 次抽帧（防重复录入） | 按实测调 |
| `confirm_word` | `"确认"` | 检出即「成句」，把词序列交给 Agent | 跟 A 组对齐 |

## 7. 期望的输出样例（用来对齐认知）

一段「你好 → 身份证 → 丢失 → 补办」的视频，理想输出：

```json
[
  {"frame_idx": 10, "word": "你好",   "conf": 0.96, "bbox": [190, 110, 390, 340]},
  {"frame_idx": 35, "word": "身份证", "conf": 0.94, "bbox": [205, 115, 405, 345]},
  {"frame_idx": 60, "word": "丢失",   "conf": 0.89, "bbox": [195, 105, 400, 340]},
  {"frame_idx": 85, "word": "补办",   "conf": 0.93, "bbox": [200, 112, 415, 350]},
  {"frame_idx": 110, "word": "确认",  "conf": 0.97, "bbox": [210, 120, 410, 350]}
]
```

经 `frames_to_words()` 之后：

```
words     = ["你好", "身份证", "丢失", "补办"]
confirmed = True          ← 检出「确认」手势，触发成句
```

交给 `agent.parse_semantics(["你好","身份证","丢失","补办"])` 之后：

```
translation = "工作人员您好，我的身份证丢失了，请问怎么办理补办？"
answer      = "【政务导办回答】补办身份证请携带户口本原件，先到 2 号人像采集室免费拍照，"
               "随后到 3 号户政窗口办理，工本费 40 元。"
```

**注意最后一步没有"确认"这个词** —— 确认手势是控制信号，不进语义。
