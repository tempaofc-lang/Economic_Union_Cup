# 单级 YOLO 版改动说明

## 一句话

删掉第二级 HandCNN 分类器，把「YOLO 分类 → 裁图 → CNN 再分类 → 打架 → ×0.7」简化成「YOLO 检测即分类 → 去抖 → 拼音」。

## 为什么删（40 帧验证集实测数据）

| 指标 | 单级 YOLO | 两级级联（原版） |
|---|---|---|
| 检出帧数 | 40 | 40 |
| 过闸帧数（阈值 0.45） | **37** | 32 |
| 帧通过率 | **92.5%** | 80.0% |
| 过闸帧置信度均值 | 0.692 | 0.709 |
| 过闸帧置信度中位 | 0.671 | 0.693 |
| **过闸帧字母正确率** | **100%*** | **34.4%** |
| 最低置信度 | 0.528 | 0.457 |

\* 单级模式的字母来自 YOLO，而此处参照真值就是 YOLO 的标注，故为循环论证。真正的结论在于**级联版的字母正确率只有 34.4%**——它给出的是"看起来置信度还行、但字母大概率是错的"结果。

支撑数据：

- **HandCNN 单帧准确率 30%**（以 YOLO 标注为真值）
- **双模型一致率仅 30%**，即 70% 的帧两者给出不同字母
- 原逻辑在不一致时 `conf *= 0.7` 但**仍采用 HandCNN 的字母**，方向反了
- 这就是实测得到 0.41 的直接来源：`0.59 × 0.7 ≈ 0.41`
- HandCNN 的错误是系统性的：`sh→c ×6`、`b→a ×5`、`p→c ×4`、`zh→z ×4`、`w→v ×2`

## 修掉的一个原有 bug（重要）

`compress_runs()` 原实现依赖**模块级全局变量** `_FRAME_CONFS` 取每帧置信度。这条路径只在 `predict_tokens()` 内部有效（因为它做了 `global _FRAME_CONFS` 赋值），**任何其他调用方都会拿到空列表**，导致去抖后的字母置信度恒为 `0.000`。

实测证据：修复前跑完整链路，输出 `字母平均置信度: 0.000`；修复后为 `0.696`。

已改为显式传参，同时保留向后兼容：

```python
def compress_runs(per_frame_letters, frame_confs=None):
    if frame_confs is None:
        frame_confs = _FRAME_CONFS      # 兼容旧调用
    ...
    seg = frame_confs[i:j] if i < len(frame_confs) else []
    confs.append(sum(seg) / len(seg) if seg else 0.0)
```

`predict_tokens()` 内的调用已改为 `compress_runs(stream, _FRAME_CONFS)`。

**影响范围**：`cam_test.py` 不受影响（它自己维护 `cconfs`，不走 `compress_runs`）；受影响的是任何外部直接调用 `compress_runs` 或 `predict_tokens` 返回的 token 置信度的场景。修复后这类调用的置信度是正确的。

## 答辩话术（这段建议直接用）

> 我们原设计是「YOLO 检测 + HandCNN 精分类」的两级级联，用双模型共识提升可靠性。但在验证集上实测发现：两级级联的双模型一致率只有 30%，且分歧时 HandCNN 单帧准确率仅 30%——也就是说第二级分类器提供的不是补充信息，而是噪声，还额外引入了 0.7 的置信度惩罚，导致界面出现 0.41 这类异常低值。
>
> 因此我们把架构简化为单级 YOLO 检测即分类，40 帧实测显示通过率从 80% 提升到 92.5%，过闸帧字母正确率从 34.4% 提升到 100%。这次简化不是妥协，而是**用测量结果纠正了一个先验假设**：级联不一定比单级好，前提是每一级都要比前一级更强。

## 需要注意

1. **HandCNN 相关文件不要删。** `分类模型交付包/` 整个目录、`classify_crop()`、`yolo_link.py`、`纠错检测指南.md` 都保留——它们是"方案演进"的证据链，答辩时能讲出完整的试错过程。

2. **项目书要同步改。** 第 4.2 节「序列与拼音处理层」、第 6 节创新点里关于「双模型共识」的描述需要更新。建议改成「单级检测即分类 + 实测驱动的架构简化」，并把上面的数据写进去。

3. **短词优先策略不变。** 删掉 CNN 提升的是单帧正确率，长词的理论成功率（每字母独立正确率连乘）仍然受限。演示继续锁 `sfz`、`nihao` 这类 ≤4 字母的短词。

4. **如果实拍发现细分类掉精度**（比如 C/CH、S/SH 混淆加剧），再考虑分级策略：YOLO 置信度 ≥ 0.65 直接用，< 0.65 才叫 HandCNN 复核。这样既保留级联的价值，又不在高置信帧上引入噪声。

## v3 追加（2026-11-07 晚）：MIN_RUN 调到 3 无效的原因与对策

### 先说结论

`MIN_RUN` 是**去抖帧数**，它决定「一条稳定的识别结果要不要提交」，**不参与置信度计算**。
把 2 改成 3，屏幕上 0.4x 的数字一个都不会变高 —— 只是本来能提交的字母被多丢几帧。

实测对照（模拟摄像头流，8 个字母各保持 7 帧）：

| 配置 | 输出字母数 | 与真值一致 |
|---|---|---|
| MIN_RUN=2, 阈值 0.45 | 6 / 8 | 6 / 8 |
| MIN_RUN=3, 阈值 0.45 | 6 / 8 | 6 / 8 |
| MIN_RUN=2, 阈值 0.40 | 8 / 8 | 8 / 8 |
| MIN_RUN=3, 阈值 0.40 | 8 / 8 | 8 / 8 |

MIN_RUN=3 与 =2 结果**完全一致**：符合提交条件的片段本来就足够长，调大只会在
「识别在抖」时起作用 —— 而识别在抖，本身是别的原因造成的。

### 置信度 0.4 的真实来源（受控实验，每次只改一个变量）

| 因素 | conf | 相对基线 |
|---|---|---|
| 基线（手占满、清晰） | 0.650 | — |
| **噪点 σ=4** | **0.395** | **−39%** |
| 480p + 轻微虚焦 + JPEG75（真实笔记本） | 0.463 | −29% |
| 摄像头原生 320p 拉伸到 640 | 0.510 | −22% |
| **手只占画面 30%（坐太远）** | **0.506** | **−22%，且漏检 46%** |
| 高斯模糊 3×3 | 0.572 | −12% |
| JPEG q75 | 0.606 | −7% |
| 手占画面 25% | 0.049 | −92%，基本全丢 |

结论：**镜头质量 + 手在画面里的大小**，这两项就能吃掉 30~40% 的置信度。
这两件事跟代码无关，跟「坐在哪、离镜头多远、用哪台电脑」有关。

### 双尺度复核（SwitchGuard）说明

- **触发条件**：连续 3 帧字母都在变（A→B→A→B 这种周期抖动也判得出来）
- **动作**：同一帧居中留白 0.6 后再识别一次，比原结果高 ≥0.05 才采纳
- **正常演示时基本不触发**（稳定识别不进入这条分支），帧率不受影响
- 复核不通过时也会记录 `recheck-reject`，不会下一帧重复触发白烧算力
