## 1. 全员共同底层（D1 上午 09:40–12:40，五个人一起）

**这一层不是"在教技术"，是在拆掉最贵的两种时间浪费：环境起不来、看不懂请求为什么失败。**

五个人坐一起做，谁先跑通谁帮别人。**李东瑞主持**（他本来就要写 `setup.ps1`，正好边写边讲）。

### 1.1 工程跑得起来（60 分钟）

目标：`git clone` → `setup.ps1` → `run_dev.ps1` → 浏览器打开界面，**五台机器全部跑通**。

| 要学 | 资源 | 学到哪停 |
|---|---|---|
| 虚拟环境是什么、为什么要有 | [Python 官方教程 · 虚拟环境](https://docs.python.org/zh-cn/3/tutorial/venv.html) | 会建 venv、`pip install -r requirements.txt`、知道"没激活环境就装错地方了"这件事 |
| 依赖装在哪、怎么看装没装上 | `pip list` | 能自己判断"这个包到底装没装上" |

> 这一节的实际价值：**李东瑞的 `setup.ps1` 能不能一次跑通，直接决定后面三天有没有人被环境绊住。** 请在这一节当场把所有报错清干净，不要留到下午。

### 1.2 HTTP 与 JSON 心智模型（45 分钟）

**这一节是全套里最重要的一节**，比任何语法都重要。因为五个人日常接触的东西全是它：`/api/agent` 是 HTTP，返回的东西是 JSON，`/docs` 页面测的也是 HTTP。

要建立的心智模型只有四个问题：

1. **谁在问、问谁**（前端发请求 → 后端收请求）
2. **问了什么**（URL 路径 + 方法 GET/POST + body）
3. **回了什么**（状态码 200/404/500 + body）
4. **怎么看**（浏览器 F12 的 Network 面板）

| 要学 | 资源 |
|---|---|
| HTTP 概述 | [MDN · HTTP 概述](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Overview) |
| JSON 是什么 | [MDN · JSON](https://developer.mozilla.org/zh-CN/docs/Learn/JavaScript/Objects/JSON) |

**现场演练（必做，10 分钟）**：打开任意网页 → F12 → Network → 点一个按钮 → 找到那条请求 → 念出"它请求了哪个 URL、方法是什么、返回了什么"。**五个人轮流念一遍。**

### 1.3 Git 最小集（30 分钟）

只学五条，**用 VS Code 的图形界面也行，不要求命令行**：

`clone` / `pull` / `add` / `commit` / `push`

**不学**：分支、rebase、merge conflict 处理、PR 流程。
（真遇到冲突就喊李东瑞，5 个人的小项目不会天天冲突。）

| 要学 | 资源 |
|---|---|
| Git 起步 | [Git 官方文档 · 起步](https://git-scm.com/book/zh/v2/%E8%B5%B7%E6%AD%A5-%E5%85%B3%E4%BA%8E%E7%89%88%E6%9C%AC%E6%8E%A7%E5%88%B6) |

### 1.4 排错决策树（45 分钟）★ 最高性价比

见 [§5 完整决策树](#5-排错决策树全员必背)。**现在就要练一遍**：

> 李东瑞故意把后端关掉 → 李彤去点"开始识别" → 让她按决策树在 3 分钟内说出"问题在后端没启动"。

练两三轮，把三种常见故障各走一遍（后端没起、路径写错、字段名不对）。

**这条决策树请贴在群公告里。** 它的作用是：把一个"卡两小时不敢问"的问题，变成一个"30 秒能自己定位"的问题。

## 2. 组 A：古宇轩 + 吴夏云 —— Agent 组合课

**为什么两个人一起学**：一个写机器，一个写机器要吃的全部内容（知识库、prompt 文案、评测用例）。如果吴夏云不懂 `prompt` 在干什么，她写的知识库就是"给人看的说明书"而不是"给模型用的上下文"；如果古宇轩不懂政务表述，他调出来的 prompt 会像技术文档而不像窗口工作人员说话。**两个人必须共享同一套概念。**

### 2.1 共同必学（合计约 4 小时）

| # | 学什么 | 资源 | 时长 | 学到哪停 |
|---|---|---|---|---|
| 1 | LLM 调用的基本形状 | [DeepSeek API 文档](https://api-docs.deepseek.com/zh-cn/) | 40min | 能跑通一次 `chat.completions.create`，懂 `messages` 的 role 是干什么的 |
| 2 | 参数与限制 | [API Reference](https://api-docs.deepseek.com/api/create-chat-completion) | 30min | 知道 `temperature`、`response_format`、`max_tokens` 各管什么 |
| 3 | **JSON 结构化输出** | `response_format={"type":"json_object"}` + prompt 写清字段 + `json.loads` 失败重试 | 60min | 连续 20 次调用都能 `json.loads` 成功 |
| 4 | **Prompt 怎么写"像人话"** | 自己迭代：写一版 → 看输出 → 改措辞 → 再跑。没有教程能替你做完 | 60min | 见下方 §2.3 |
| 5 | Tool / Function Calling | [OpenAI · Function Calling 指南](https://platform.openai.com/docs/guides/function-calling)（概念通用，换 base_url 即可） | 60min | 能写出"模型要工具 → 你执行 → 结果喂回 → 最终答案"的循环 |

> 注意：当前模型名是 **`deepseek-flash`**，`base_url` 用 `https://api.deepseek.com`。README 里旧的 `deepseek-chat` 写法已过时。

### 2.2 明确不要上向量数据库

知识库只有 30 条政务事项。用关键词匹配 / 简单字符串相似度**足够**。LangChain、Chroma、FAISS、embedding 在这个量级上是纯复杂度负担。

一句话：**30 条数据用手写检索，30000 条才需要向量库。**

### 2.3 两个人的分工学什么

**古宇轩（写代码那半）**：重点在第 1、4、5 项。要练成的是——**错误输入不让程序崩**。三个必须过的检验：

1. 喂 `["身份证","丢失","补办"]` → 返回合理译文 + 导办回答 + `tool_calls` 里有 `query_gov_kb`
2. 喂 `["身份证"]`（只有一个词）→ 返回 `clarify` 问清业务，**而不是硬猜**
3. 喂 `[]` 或 `["乱码测试"]` → **不抛异常、不返回 None**，要有兜底

第 3 条特别重要：**所有外部 API 都会超时。** 写好 `try/except` + 降级到 `rule_fallback.py`，决赛断网时这个兜底会救整个演示。

**吴夏云（写内容那半）**：重点在第 2、3、4 项，加上 §6.2 的 JSON 格式。要练成的是——

- 能看出模型输出**哪里"不像政务窗口该说的话"**，并改 prompt 改好它
- `gov_kb.json` 每条都有 `aliases`（检索用）和 `source`（出处，承诺书第 2 条要求）
- 能自己写一条评测用例并判断"这条算通过还是不算"

**她的验收**：`python -c "import json; json.load(open('gov_kb.json', encoding='utf-8'))"` 成功，30 条 `source` 都不为空。

### 2.4 明确不要学（针对这一组）

LangChain / LlamaIndex / AutoGen / CrewAI / 任何 Agent 框架源码。**自己写 200 行循环比调框架稳。** 也不学微调、RAG 高级技巧、多智能体协作。

## 4. 独立线：杜佳润 —— 视频与 PPT

**目标：让完全不了解项目的评委在 3 分钟内看懂"这是什么、解决什么问题、做得怎么样"。**

这条线**不占用编程学习时间**，和别人并行。

| # | 学什么 | 要点 | 时长 |
|---|---|---|---|
| 1 | 剪映基础 | 导入 / 分割 / **"识别字幕"自动生成字幕**（省一半时间）/ 导出 1080p | 60min |
| 2 | 录屏 | Windows 自带 `Win + G`，或 OBS。**分辨率 1920×1080，帧率 30** | 20min |
| 3 | 三段式叙事 | 痛点 40s → 演示 110s → 成效 50s。详见 [分工文档 §4.5](05_B组详细分工与项目框架.md) | 40min |

### 三个具体拍摄建议

1. **不要写"据调查我国有 XXXX 万听障人士"。** 评委听过一百遍。改成一个具体场景：一个人在窗口比手语，工作人员表情困惑，递出纸笔。
2. **演示段不要切碎。** 一次完整办事一镜到底，不插"接下来我们看下一个功能"。连贯性本身就是产品力的证明。
3. **失败要有一次。** 故意演示一次识别失败 + Agent 追问澄清，比全程完美更可信。**会承认边界的系统才像真系统。**

**验收**：成片给一个不知情的同学看，看完问他"这个系统是干什么的"，他答对了就过关。

**明确不要学**：After Effects / 三维软件 / 数字人生成。手语数字人的视觉反馈**用预录的真实手语视频片段实现**——效果更好、成本为零。

## 5. 排错决策树（全员必背）

> **请把这一节贴在群公告里。**

```
现象：点了按钮没反应 / 页面没出现数据
│
├─ 第 1 步：按 F12 → Console，有没有红字？
│   ├─ "Failed to fetch" / CORS  → 大概率是后端没启动，或端口不对
│   ├─ 404                       → 路径写错了，去对 docs/api.md
│   └─ 500                       → 后端崩了，跳到第 2 步
│
├─ 第 2 步：看后端终端（跑 uvicorn 那个黑窗口）有没有报错？
│   └─ 有 → 把最后 3 行复制到群里（不是截图，是文字）
│
├─ 第 3 步：打开 http://127.0.0.1:8000/docs ，手动测同一个接口
│   ├─ /docs 能通、前端不通  → 前端问题 → 找李彤
│   └─ /docs 也不通          → 后端问题 → 找古宇轩 / 李东瑞
│
└─ 第 4 步：都通但数据不对
    └─ 把后端返回的 JSON 和 docs/api.md 的字段名逐字对一遍
       （99% 是字段名拼写或大小写不一致）
```

**配套两条规定：**

1. **卡住超过 30 分钟，必须发群里。** 不许自己耗两小时——这不是努力，这是把全组的风险留给自己。
2. **报错发文字，不发截图。** 文字能搜索、能复制给别人试。

## 7. 明确不要学的清单（这张表比上面所有表都省时间）

| 不要学 | 为什么 |
|---|---|
| React / Vue / Angular | 前端是纯 HTML，已写好 |
| TypeScript / Webpack / Vite | 没有构建步骤，直接打开就跑 |
| LangChain / LlamaIndex / AutoGen | 200 行手写循环更可控，框架调试吃掉整个工期 |
| 向量数据库（Chroma / FAISS / Milvus） | 30 条知识库，关键词匹配足够 |
| Docker / Kubernetes / CI-CD | 没有部署需求 |
| 微调（LoRA / QLoRA） | 不训自己的大模型 |
| 数字人生成 / 三维动画 | 用预录手语视频替代，效果更好 |
| 连续手语句子识别 | 明确不在初赛范围内（团队已做对判断） |
| 数据库设计 / SQL | 用 JSON 文件即可 |
| Git 分支 / rebase / PR 流程 | 5 人小项目，`pull` + `push` 够用 |

## 8. 一周后自查

如果 D2 冲刺顺利完成，**每个人**应该能回答这三个问题：

1. **我负责的文件在哪个目录，我的上游是谁、下游是谁？**
2. **别人怎么验证我做完了？**（不是"我做完了"，而是"他能看到什么"）
3. **如果我的机器突然断网 / 崩溃，项目会卡在哪里？**

第 3 题答不出来的地方，就是要提前准备兜底的地方。
